## 能力和限制

1. 附件原件与索引分开保存，文件名不当磁盘键，检索和取回受本人身份、会话及路径检查约束。文本仍走收件和 worker 流程；本版没有新增跨批文字摘要或通用长期对话记忆。
2. 单件默认上限为 100 MiB，普通保留期 30 天，总量 5 GiB，钉住也计入容量。到期仅成为清理候选；本版 GC 仅预览，不自动删除原件。失败留样默认关闭。
3. 已识别风险文件会提醒，但桥不执行、解包或进行病毒检测。未知格式或 HEIC 原件可保存，不代表平台已经能看图。padding 通过不等于内容验证通过；解密结果冲突会保留明确失败信息。
4. 发送仍受有限预算和持久账本约束。API 接受、模型读到、手机收到分别验收；unknown 不自动重发，不能用清账本或回滚游标来“恢复”。
5. 宿主、微信平台及助理平台各有生命周期与网络限制。代码不包含已验证的 Dot / PEPE 云托管能力，也没有连续多日稳定运行保证。

## 安装与目录

[README](../README.md)提供安装和当前测试入口，[公共启动指南](lines/01-core/QUICKSTART-V1.md)提供绑定顺序。新账号首次绑定前不要先放入 backend 配置；已有账号更新不要另行扫码或重置运行目录。

本次 Muse Linux 现场确认的目录权限为实例根目录 0750、`state` 和 `inbox` 0700，均无 SGID。某些共享父目录会使新目录继承 SGID，导致严格 0700 检查失败。操作者须核对实际归属和每个受管目录；不要对整棵目录递归放宽权限，也不要删除状态来绕过检查。具体设置以自己的实例、用户与部署检查结果为准。

Muse 升级须同步匹配 Python 包、Hook 脚本、adapter 与平台实际 prompt。仓库 Hook JSON 中的投递目标是占位符，不能整份覆盖真实平台配置。参见[目标保全检查](lines/02-muse/MUSE-ATTACHMENT-003-DEPLOYMENT.md)与[worker 协议](../hooks/WORKER-STATE.md)。
