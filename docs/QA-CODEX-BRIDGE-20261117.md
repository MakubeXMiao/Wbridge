## 已知 P2：发送结果未知时的切换检查

编号：`QA-ROUTE-UNKNOWN-SEND-01`。责任：01 公共底座。状态：**尚未修复，启用多后端切换前必须处理**。

复现情景：PEPE 已完成，回复进入发送；微信发送请求的确认丢失，`failed/` 保存了发送 unknown，但模型任务仍为 succeeded、输出阶段仍为 admitted。这时如果额外配置了其他后端，现有 `/backend` 可能允许切换，`/status` 也没有完整显示发送不确定性。

没有观察到自动重投、跨账号发送或凭据泄漏。当前 PEPE-only 示例配置没有另一个可切换目标，因此不阻止这一受限文字分支上传。它不能据此被标为多后端切换已通过；发送 unknown 的状态展示缺口也仍然存在。

修复验收必须覆盖：未知发送可见；忙闲切换读取持久化的发送状态并拒绝切换；核对原回复后才解除阻塞；队列、游标、收据和原远端 task 映射保留；不通过自动重发来消除未知状态。
