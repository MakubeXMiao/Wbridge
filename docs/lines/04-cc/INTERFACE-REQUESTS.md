# 04 CC 桥向 01 提交的接口需求

任务：`WBR-04-20261023-001`。日期：2026-10-23。状态：**候选，供 01 形成公共契约并交用户确认；本轮不实现适配**。

## 1. 责任与接入方式

01 持有微信收发、附件落地、队列、租约、任务台账、路由、CLI/打包和对用户的投递。04 只持有 Claude 执行端的启动、事件转换、会话引用、审批回调与取消。04 不读取微信 token，不复制 sender/Store，不直接写 outbox。

建议公共接口支持一个独立 SDK 宿主进程，避免把某种语言的回调或运行时版本直接塞进公共 Python 包。候选包括 Python Agent SDK 宿主、TypeScript Agent SDK 宿主和 CLI 子进程；最终目录、语言、最低运行时和 API 名称由 01 协调。当前公共包仍声明 Python >=3.8，不能未经确认提高版本门槛。

需要微信内审批时，优先评估 SDK 的双向回调路径。纯 `claude -p` 的输出流本身不等于审批通道；CLI 需要另外配置 permission host。官方依据：[审批回调](https://code.claude.com/docs/en/agent-sdk/user-input)、[CLI 参数](https://code.claude.com/docs/en/cli-reference)。

## 2. 调用与事件的最小要求

以下是需求字段，尚不是已生效的公共 schema：

| 位置 | 需要表达的内容 | 原因 |
| --- | --- | --- |
| 调用身份 | `task_id`、`attempt_id`、后端名、调用方会话键 | 重试、迟到事件和跨用户会话必须可区分 |
| 输入 | 本轮文本、由 01 验证的附件引用、允许的工作目录与工具策略引用 | 用户文本/路径作为数据传递，不拼成 shell；不让后端自行读取公共队列 |
| 会话 | 可选的不透明 `session_ref`，附账号/安装实例命名空间 | 指定续聊目标；不能用“最近一条会话”猜测用户 |
| 返回句柄 | 本次运行 ID、接收状态、事件订阅/读取方式 | 启动成功不等于任务完成，更不等于微信送达 |
| 事件关联 | 运行 ID、attempt、单调序号、事件类型、时间 | 去重、乱序处理、进程重启后的恢复 |
| 最终结果 | 文本/结构化结果/受控附件引用、后端 session ID、结果状态、退出信息 | 只将已核对的本轮终态交给 01 入队 |
| 失败 | 可识别错误分类、脱敏诊断、是否已发生工具副作用、是否结果不明 | 不能看到 stderr 或非零退出就盲目重放整次任务 |

需要区分的事件至少有：开始、进展、会话已建立、待用户审批、待用户补充信息、最终结果、失败、取消确认。未知后端事件可以记录类型并忽略，不把它当作完成。

Claude 的 token 增量、assistant 消息、API `message_stop` 和工具输出均不足以单独宣告整次任务完成。SDK 的 `result` 事件还要检查 `is_error`，不能只看 `subtype=success`。依据：[流式输出](https://code.claude.com/docs/en/agent-sdk/streaming-output)、[Python ResultMessage](https://code.claude.com/docs/en/agent-sdk/python#resultmessage)。

01 还需裁定：终态与进程退出如何对账；终态后的迟到内容如何隔离；消息大小/事件积压上限；传输断开时如何恢复而不重复执行。

## 3. 会话续接与并发

3.1 由 01 绑定“微信用户/会话 → 后端实例 → session 引用”，04 返回真实 session ID。不得跨账号、跨安装实例直接复用；原始 transcript 作为私有运行数据管理。

3.2 多会话场景必须指定 `resume`，不使用全局 `--continue`/`continue: true` 作为路由。若选择持续连接的 Python `ClaudeSDKClient`，仍需公共会话映射与单会话串行约束；不能将一个客户端任意共享给不同用户。依据：[会话管理](https://code.claude.com/docs/en/agent-sdk/sessions)。

3.3 进程重启、session 不存在或损坏时，应返回明确状态，由用户/01 决定是否新开；不得悄悄丢弃上下文再声称续聊成功。会话续接不恢复已改过的文件。

## 4. 审批与问题响应

SDK 的 `canUseTool` 可以暂停执行并等待响应；已被权限规则自动放行的工具不会再次触发这个回调。不能将它当作所有工具调用的统一拦截点。依据：[权限评估](https://code.claude.com/docs/en/agent-sdk/permissions)。

| 公共侧需要承担 | 04 需要承担 |
| --- | --- |
| 持久保存待审批请求并向正确微信用户展示脱敏摘要 | 捕获后端 tool/use 请求及其关联信息，等待本次请求的明确决定 |
| 验证响应者、task/attempt、一次性请求 ID、输入摘要哈希、有效期 | 将允许/拒绝映射为 SDK 响应，防止旧响应用于新工具调用 |
| 区分一次允许与长期权限变更；重复/过期/取消响应有明确回执 | 不自动采纳权限扩展建议，不默认启用 bypassPermissions |
| 为 `AskUserQuestion` 保存选项和用户答案，而不是强行转成允许/拒绝 | 返回真实问题响应；不伪造用户选择 |
| 决定审批到期、服务重启、会话被替代时的状态与通知 | 尽力解除回调等待，保留结果不明信息，不继续使用失效授权 |

审批可以长时间等待，不能以固定后台心跳无限续接现有收件租约。须由 01 设计它与当前 90 秒软租约/570 秒硬上限的关系。官方已有 `PreToolUse` defer 路径，可作为后续候选；本轮未验证其持久化/恢复，不把它视为现成可用能力。[用户输入与延迟审批](https://code.claude.com/docs/en/agent-sdk/user-input)

## 5. 取消、超时与失败

5.1 取消 API 必须按运行/attempt 定位，幂等返回“已请求、已确认、已终态或状态不明”；发出信号不等于执行已取消。等待审批时也必须能结束等待，取消后的迟到允许不得恢复执行。

5.2 SDK `interrupt()`、宿主 abort/关闭与 CLI 进程信号含义不同；后端应先请求停止，再在有界等待后关闭自己拥有的进程及子进程。具体确认条件由版本验收决定。CLI SIGTERM 可能没有本轮最终 result，不能将缺失 result 当成功。[headless 终止说明](https://code.claude.com/docs/en/headless#stop-a-run-with-sigterm)

5.3 请分别提供总执行截止时间、审批有效期、取消宽限期、stdout 无进展阈值和输出上限。`max_turns`、估算费用上限都不等于墙钟超时。工具可能已经改文件或发起外部动作；超时/中断不是事务回滚。

5.4 错误至少区分：未安装/版本不支持、未认证、参数错误、session 不存在、权限拒绝、模型/网络/配额错误、进程异常、超时、协议不完整、结果不明。原始日志只落本机私有证据目录；共享事件与微信回复只给必要脱敏摘要。

5.5 固定 TS SDK 0.3.309 的 `interrupt()` 类型说明允许返回仍待执行的消息 receipt；同版本 result 也可能带 `queued_turn_count`。若后续选择 streaming input，01 的取消协议必须覆盖待执行输入和当前执行，不能只中断当前轮次后默认队列已清空。此处为静态接口需求，未做真实取消验收。
