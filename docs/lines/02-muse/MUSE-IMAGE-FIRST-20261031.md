# Muse 图片诊断兼容 · 001-IMAGE-FIRST

本批基于固定运行源码 `1f0160bc42e016cb47c273c091575f296c3d9634`，接入经 00 转交的公共契约提交 `719020ace0c7733b96b0a1c1afaf16eb6b690941`。用户已授权隔离代码修改与合成验证；本说明不表示已部署或手机验收通过。

1.1 原件保存、目录索引、本人 query/get/reference 和带账本 reply 已有实现，本批复用。Muse 适配仅向独立诊断白名单增加 `http_body_incomplete`，不另建收发、目录或重试器。三个消息快照入口准确为 begin、refresh、reply 返回 needs_refresh；它们共用同一个净化器。

1.2 新原因表示公共接收侧已证 HTTP 报文体不完整，属于下载阶段。具体判定按公共冻结契约，不能只因普通超时、缺声明长度、解密失败或“图片打不开”就归入此类。该原因只能与 failed 配对；不能解释为图片已保存、密钥配对有误或可以无条件重发。

1.3 可选 V1 的版本、字段、值域与预算保持：每项只包含 item_index/source/outcome/downloaded_bytes/reason；每原 item 最多两个不同来源，每来源仅最终一次摘要，字节为该最终 attempt 实收值，非累计值。全体最多保留 16 项，只扫描前 32 项，紧凑 UTF-8 至多 4096B。未知原因和敏感扩展照旧剥离；不导入 URL、key、原异常、HTTP 头、attempt 明细或正文。诊断丢弃不能改变有效正文、可用附件路径及失败总数。

1.4 诊断随安全快照提供，不保存到私有会话正文或回复任务；仅净化后的业务快照参与 digest。needs_refresh 不入队，显式刷新后的最终回复仍只入队一次。API accepted 与手机实收分开；unknown 和关闭句柄不自动重试。保存/取回/图片读取及回发沿用已有附件身份、受控路径和账本，不因新原因取得额外权限。

2.1 单元验证沿用 `hooks/tests/test_muse_worker.py`：保留原 V1/坏类型/隐私/16-32-4096 预算用例，新增原因穿过三个入口，以及伪成功、私有后缀不能冒充有限原因的用例。

2.2 `hooks/tests/test_muse_image_diagnostics.py` 要求与冻结公共净化器一起运行，缺少新公共契约即明确失败。它实际经过公共 receiver 净化、inbox 写入、WorkerState 和三个 adapter 入口，验证首源不完整、次源成功与另一失败附件共存、保留有效材料、敏感字段剥离和一次入队。仅下载边界为合成替身，不证明真实 AES、图片验证、目录保存、Muse 工具读取或手机收到；这些须由最终公共组合及后续已授权真实验收分别证明。
