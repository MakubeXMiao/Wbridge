# 012 公共媒体与运行维护修复

基线 b43e55777cdefbcd84f07ed77ec7e2a18e7f81c5。本候选与011 PEPE独立；仅公共代码和合成离线验证，不激活私人留样、不清理现网数据、不部署或重置微信/Hook/队列/游标。

## 媒体验证与内部诊断

图片解密候选以及明文回退均须通过隔离进程的 Pillow verify、重新打开并逐帧 load；不再凭魔数落盘。图片收件沿用 JPEG/PNG/GIF/WEBP 魔数集合；验证器另具BMP解码能力，但未扩展现有wire图片识别或fallback。保留原 AES 派生/模式、解密优先、有效候选歧义拒绝、param→full_url、100MiB明文和原子替换。单源坏体可回退；全部失败不覆盖旧目标。Pillow显式直依赖只是表达新直接用途，原qrcode[pil]已间接声明，不能据此声称历史缺包。

单传输最多16个不同候选、累计解码墙钟预算3秒；本进程一次仅一个验证子进程。输入最多100MiB；每边≤16384、单帧≤1600万像素、最多32帧、累计≤3200万像素、单帧计划解码预算≤256MiB。子进程CPU软2秒/硬3秒，Linux地址空间硬512MiB；macOS部分Python不支持该硬限制，采用RSS采样守护和几何预算，超过512MiB即终止，**不是分配器硬上限**。超时/资源失败终止并回收子进程，保守拒绝图片。慢机器或超预算的合法大图也可能拒绝，不能将该限制写成格式损坏根因。HTTP120秒上限及Hook90/570保护不变；没有后台盲续租。

可选 `media_diagnostics` 详见 [固定V1契约](INBOX-MEDIA-DIAGNOSTICS-V1.md)：16条/扫描32条/4096字节/每item最多两源。仅本地固定来源、实际下载字节、结果和有限原因；坏诊断降级而不破坏有效文字/附件。首败次成的附件不记失败，真实失败计数独立于诊断截断。02负责平台嵌套净化/digest/Hook回执；本线不替换其适配器。

## 日志与监督

新受控启动通过独立 pipe relay 收集 stdout/stderr；relay 单次最多读64KiB，持锁写入、轮转时重新打开日志FD。serve.log每份≤5MiB、活动加两备份≤15MiB；监督JSONL每份≤256KiB、活动加一备份≤512KiB。无轮转临时副本，锁文件为空。争锁/磁盘/轮转失败可丢日志块，继续drain，不把日志当可靠账本，也不因日志异常终止服务。

既有直接持有旧文件FD的健康进程先按巡检 copytruncate 保留同inode；不能承诺两次巡检之间的硬上限，也不为切换日志主动重启。下一次正常受控更新/启动后，持续边界生效。直接命令行serve的外部重定向由调用方管理；本机制约束supervise管理的日志文件。

监督事件固定版本、reason/action/result、旧新PID/start、heartbeat及有限时间；无命令tokens/完整异常。TERM请求、KILL请求、停止观察和新启动分别记录，旧退出码/信号无直接wait证据时为unknown；只有relay对其亲生子进程wait才可记录真实退出码/信号。新启动须ACK、真实childPID与独立身份/start一致。120秒心跳、180秒启动、TERM后等待/重核身份、90/570不变；观察日志失败不改变监督决定。

## 媒体保留：默认零修改dry-run

`wechat-bridge media-gc --base /ABSOLUTE/RUNTIME` 默认只读。构造与规划不调用Store，不创建目录/锁/DB/WAL/SHM，不输出文件路径、消息或私有引用；报告计数/字节及未能回收的超额。默认TTL7天、总目标512MiB、最低年龄24小时，可显式调整。TTL/配额只挑无引用的普通文件；staging/dot文件永远保留，目标配额可因保护引用而无法达到，不是媒体目录硬大小承诺。

新版每个Store在任何媒体操作前持有共享 `state/media_usage.lock`，直到该客户端停止并close/销毁。它覆盖下载落盘到inbox发布、worker、dispatcher、CLI的所有生命周期，宁可阻塞清理。apply必须 `--apply --offline-maintenance`，且新版Store共享锁/serve锁/receipt锁/backend-worker锁均能排他取得；整个扫描、重查和unlink共用排他边界。**先停止全部写者，尤其旧无pin版本与外部平台；指定全部自定义worker状态根 `--worker-root`，否则不支持清理。** 本候选没有执行这些现网动作。

每个Store另持有私有 `state/media_usage_clients/<随机ID>.lock` 零字节独立锁，防总锁被意外替换后隐藏活客户端；close仅移除自己的控制锁，崩溃遗留的未锁定文件不代表活客户端。GC另检查这些锁，清理期间复核总锁inode。根须为可信同用户的私有目录，协作写者必须遵守协议；不支持同UID恶意删除整个协调目录/绕过锁的外部写者。fresh-login只豁免格式/权限/零字节均合格的本机制控制文件，不把任意文件当空状态。

引用扫描覆盖legacy/managed inbox、所有outbox含sending/failed/sent、reply_batches和整个运行根的JSON、backends.json明确的legacy_state_dir、显式worker roots，以及managed SQLite jobs/inputs/approvals/outputs。数据库immutable只读且遇任何WAL/SHM/journal即全局拒绝，不忽略未合并引用；不读取真实宿主的默认外部目录来猜引用。损坏/未知数据库、读取/权限异常、扫描超限或链接/硬链接均保守全局不删。最多10000扫描项、单JSON1MiB、合计16MiB元数据/100000值、递归16层。根归属/权限、目录链接、候选inode/大小/mtime及命名锁重核；dirfd相对unlink，仅删选中的media普通文件，不删目录、receipt、队列、账本或游标。中途故障若已发生删除，报告partial及实际计数，不谎报零删除。

## 默认关闭失败响应留样

`FailureCapture(enabled=False)` 构造、capture和cleanup均零触碰。普通CLI/serve不自动创建或启用实例；仅后续获具体采集授权的受控运行器可显式将enabled实例注入Store.failure_capture。本次只用合成样本测试。

启用后只复制本次已读响应，不新增下载/重试或网络回放。仓库外专用0700根，body/key/manifest分目录、文件0600、随机ID，无URL/host/token/context/正文。窗口持久登记、跨对象/进程共享锁，最多3传输×2源，每源≤1MiB、整体≤6MiB；截断/无效key标不可回放。预先花费额度，采集失败不退款绕过，也不改变正常下载。体与key不进日志或聊天；私有摘要只用于原宿主完整性校验。

窗口24小时到期后不再采集；启用实例的serve启动及flusher周期调用清理，采集触发也检查到期。离线/关机期间无法运行计时器，恢复受控实例后须先清理；维护者负责窗口结束停用及原宿主到期清理核验，不宣称停机仍能删除。保留空的已耗尽窗口marker防重启绕过，另开新窗口须新的具体授权。留样根/权限/链接不合格则关闭失败；捕获和清理故障不影响桥接。

### 留样R1返修：生命周期与崩溃恢复

专项QA对adeaa80发现两项P2：普通锁争用会永久关闭TTL清理，自有JSON临时文件在硬退出后不能恢复。该旧版通用PASS保持原覆盖，不抵消专项FAIL；后续必须绑定新完整SHA重验。

采集 `enabled` 与清理 `cleanup_enabled` 分开：默认OFF/close均关闭；正常锁忙只返回 capture_busy/cleanup_busy，可在后续周期重试，不永久改变生命周期。严重验证失败暂停新采集，清理仍保留严格复核和重试入口；unknown/链接不会被当成普通锁忙或被删除。serve以清理入口可用状态调度，不因新采集暂停而遗忘已存样本。

私有控制journal只保存窗口/来源/sample登记、累计预算和cleaned状态，不存体/key/URL。最多初始化、六次来源登记和一次清理，共8个完整逻辑记录、16KiB；revision与哈希链、相邻状态单调验证共同保护原窗口和到期时间，不能替换/减少已有sample或退款。先fsync控制记录，再更新marker缓存和响应文件。cleanup先持久记录cleaned，再删除；崩溃/时钟回拨不复活已清理窗口。再次调用只报告本次实际删除数，部分失败报告已发生的数，不推断崩溃前累计结果。

marker临时名绑定已持久窗口/修订，key/manifest临时名绑定已登记window/sample/目标；有界复核权限、普通文件、链接数和总大小后，仅恢复或移除可证明归属的临时文件，已花slot和body预算不回退、不重新采集。旧marker只能按原期限/预算受控接入；旧随机.tmp和其他无归属文件继续拒绝且保留，不靠前缀盲删。当前无生产留样存量，此机制不声称自动处置任意旧临时文件。

控制日志不完整尾部但有可信前缀时，暂停新采集，不重置窗口或退款，并保留基于原期限的幂等清理能力；不能在坏尾部后盲追加后假装已修复。初始化只接受受控空根/锁/空协议目录，或有效旧marker/持久初始化记录；未登记的非空目录不接管。journal及所有允许临时文件仍计入原128KiB元数据预留，所有留样文件总上限仍6MiB，默认OFF/24小时/仓库外0700与0600规则不变。

独立R2补验旧格式迁移中断：只有原marker和整个旧格式树严格有效、journal没有任何完整行，且其0字节或残留半行精确匹配该原窗口唯一revision0记录的字节前缀时，才可重建首次控制记录；保留原窗口、额度和到期时间。没有有效旧marker的非空partial、不同窗口/内容、未知文件或链接继续保留拒绝。恢复重建再次崩溃后仍按同一原窗口核验，不生成新窗口。

有可信前缀但尾部损坏时，清理前将marker持久写为**最新可信窗口仅cleaned变为true**的严格变体，作为清理已开始的latch；不修改坏尾、不改变期限/预算/样本登记。唯一受控marker临时文件若完整等于此latch，可原子前滚并fsync，之后才删样本；其他残留不冒充清理状态。恢复后即使时钟回拨也幂等续清，采集继续暂停。此为torn分支对marker缓存的受限例外，不把任意marker当控制权威。
