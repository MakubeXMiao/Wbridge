# 提交给 01 的最小 Codex 接口要求

任务：`WBR-03-20261023-001`。状态：**供 01 形成公共契约的要求和候选，不是已确认 API；不据此开始适配实现。**

## 1. 输入与归属

1.1 01 持有消息、附件、发送者归属、队列、租约、幂等和微信投递。03 只接收已授权的执行请求及回传执行事件/结果，不直接读写真实 inbox/outbox，不复制 Store 或 sender。

1.2 执行请求至少提供 `task_id`、每次尝试唯一的 `run_id`、owner/fencing 关联信息、归一化输入、允许访问的附件引用、`cwd`、期限、显式 sandbox/approval 配置及可选的后端会话引用。后端会话引用与微信 context/lease 分开，不携带微信凭据。

1.3 会话映射由 01 定归属与持久位置，03 保存/返回后端标识。键至少隔离 backend、账号作用域和授权会话；不得默认继续桌面最近聊天。分别保存 backend thread/session/turn ID，允许缺少其中某项；只有实际返回过的 ID 才能声明可续接。

1.4 启动配置允许指定并记录 CLI 绝对路径、版本/摘要、运行目录、有限环境变量白名单和后端路线。不得继承全部宿主秘密给任意后端，不将某台 Mac 的应用路径写死为跨平台默认。SDK 包版本和它使用的 runtime 版本分别登记。

## 2. 事件与结果

2.1 事件最少可归一化为 accepted、started、progress、approval_required、final_result、terminal；保留原始事件类型及 backend ID/顺序或游标作关联。CLI 点号事件和 app-server 斜线事件由 03 适配，01 不依赖某一个 provider 的原始结构。未知事件、重复/乱序、部分 JSONL 和断流不能产生伪成功。

2.2 返回结果至少包括 `run_id`、`execution_status`、最终文本/结构化结果/明确的附件清单、后端 ID、可选 usage、错误分类、数值 exit code/信号、取消/停止状态和脱敏证据引用。诊断 stderr 与用户最终结果分开。

2.3 执行完成、结果取回与微信入队/发送/手机收到分开记录。正常进程退出只是一项证据；有效 final_result 需要当前 attempt 对应的成功终态及已取回/校验的最终产物。结果文件采用每次 run 的独立路径，拒绝复用旧文件或把空答案替换提示后记成成功。缺少终态、final、结构化校验或停止确认时记录明确失败/结果未知，由 01 决定是否可重试。

2.4 执行 completed 不代表模型所声称的业务操作已完成。待办保存、提醒建立、实时价格或外部动作有各自可观察验收，不能由回复正文自证。usage 可缺失，不能编造费用或 token 数。

## 3. 取消、期限与恢复

3.1 `cancel(run_handle)` 应幂等，并区分取消已请求、停止已确认和停止不明。app-server 请求 `{}` 不能直接映射为 cancelled；等待对应 interrupted 终态。CLI 路线应明确自己管理的 PID/进程组及清理结果，不能按模糊进程名停止别的服务。

3.2 由 01 提供绝对 deadline 与剩余 owner 预算，03 使用单调时钟监督本次运行；期限须给最终结果校验与入队留余量。旧原型 600 秒默认值大于当前 worker 从 begin 起 570 秒硬上限，不能原样照搬。租约丢失后禁止用旧身份发布结果；03 请求停止并回传结果/副作用是否仍未知，由 01 执行 fencing。

3.3 等待审批、长工具调用和进度续租如何持久化/挂起，需要 01 明确状态转移。不能把定时心跳当实际进展、绕过 90 秒静默期限或无限延长 570 秒上限。当前 Muse worker 协议不应在本线自行重定义。

3.4 终态建议可表达 completed、failed、cancelled、timed_out、outcome_unknown，同时另记停止是否确认。超时或进程已停并不能证明没有执行过副作用；不确定操作不自动换 run_id 重投。会话恢复、任务重试和消息重发是三个不同动作，恢复前核对版本及既有执行身份。

## 4. 审批与能力声明

4.1 审批请求要带独立 `approval_request_id`、所属 task/run、后端请求/thread/turn/item ID、动作/权限的脱敏说明、有效期与允许决策。响应校验原用户、作用域与原请求，迟到或重复响应不得扩大授权；拒绝/取消/超时分别记录。

4.2 首轮 CLI 候选不声明可往返审批；无法继续时明确结束/阻断。需要交互审批时，经 01 评审 app-server 路线并完成隔离测试，不能默认为 `never` 或跳过沙箱来消除审批。

4.3 能力声明至少区分“帮助/协议存在”“本地合成验证”“真实后端验证”“不支持/未知”；将 resume、事件、取消、审批、图像/文件输入、usage 各自声明。只看到 `-i` 或 localAudio schema，不承诺该账号、模型或宿主已具备对应能力。

## 5. 确认后再实施的验收清单

1.1 成功执行：记录实际 CLI/SDK/runtime 版本；取回唯一 run 的最终结果与成功终态；空结果、旧文件和只有 exit 0 都不能通过。
1.2 显式续聊：两轮任务使用同一授权 backend 会话，另一发送者和另一 backend 不串话；从保存的 ID 恢复，不用 `--last`。
1.3 事件：覆盖进度、final、失败、未知/重复/截断事件；终态与微信投递状态独立。
1.4 取消/超时：取消前、执行中、final 临界区、已终态重复取消；保存请求与停止证据，检查 owned 进程与 lease fencing；不确定副作用进入复核。
1.5 审批：明确所选路线支持后，再验证批准/拒绝/取消、过期、断线、恢复和迟到回答；不通过正文口令隐式授权。
1.6 故障：缺少认证、非零退出、模型/网络/额度错误、无 final、异常退出后孤儿进程与恢复；禁止凭提示文字或 API 接受判断成功。

这些用例尚未全部执行。真实模型测试的认证使用方式、独立工作目录和额度范围需在后续验证任务中明确；本轮没有创建 API key、启用云资源或接入真实 bot。
