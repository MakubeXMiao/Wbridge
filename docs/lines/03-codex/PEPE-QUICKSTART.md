# PEPE 独立文字接入

本页适用于第二桥 Codex 当前的 PEPE／dot2api 路线，先决条件是 PEPE 任务已经能从专用 dot2api 队列自动领取并完成工作。它不同于运行本机 Codex CLI；不要在原 Muse 目录或状态上操作。

## 1. 先完成服务与原生接单

1. 按上游原版文档部署固定 dot2api，明确 API 调用身份、工作身份、tenant 和专用队列。桥只读取指定的环境变量凭据，不把凭据放在 URL、Git、命令行参数或聊天里。
2. 在 PEPE 建立受支持的 MCP 连接，并创建该专用队列的原生事件处理任务：收到事件后查询 queued、领取、读取 payload.messages、需要时按原协议续租，将非空纯文字完成结果写回原 task。允许这些必要协议写回；其他工具沿用 PEPE 自身权限。连接、订阅、事件送达、自动领取和完成是不同步骤。
3. 用一条无私密内容先验证自动处理，确认没有另一个 worker 竞争此队列。订阅恢复后要补查专用队列，事件不保证历史回放；本分支尚无通用原生任务安装向导或自动恢复承诺。

## 2. 再绑定独立微信

在新运行目录中依次运行安装环境的 `wechat-bridge login`、`wechat-bridge wait-login`，每次通过 `WECHAT_BRIDGE_DIR` 指向同一个独立目录。二维码有时效，确认成功后才继续。

**首次扫码前不要把配置示例写进 runtime。** 首次保存账号前出现未知状态，程序会拒绝接管，这是保护机制。也不要复制其他桥的登录信息、队列、账本或游标来跳过绑定。

## 3. 保存配置并预检

扫码确认后，在该 runtime 的 `state/backends.json` 写入基于 [示例](backends.pepe.example.json) 的配置，使用权限受限的文件。替换 account_scope、instance_id、principal、tenant 和 queue 为本实例实际归属；这些不是凭据。`base_url` 是桥可访问的 dot2api API 服务，HTTP 仅允许 loopback；跨主机使用经验证的 HTTPS。

`credential_env` 指向服务管理器中预先配置的环境变量名；值由操作者在受限的本地环境配置中填写。示例没有真实值，不能拿它直接连现有实例。不要把凭据写进共享仓库。

用相同环境执行 `wechat-bridge backend-check`。应看到 backend_v1、default_backend=pepe 和 native_delegation_configured。这个预检不请求远端认证，因此 `provider_auth=not_checked` 不能当作登录或模型可用证明。既有受管数据库绑定配置和账号，运行中不可随意增删后端或改路径；变更须先有保留状态的迁移方案。

## 4. 启动与真实验收

确认同一 bot 只有一个收件进程后，在相同环境启动唯一 `wechat-bridge serve`。生产常驻与开机启动由目标宿主的服务管理器配置，本仓库不自动改系统服务。

微信先发一条无私密文字，依次核对收到、native task 绑定、PEPE 完成、微信 API 接纳和手机实收。首期只收一对一纯文字，图片／文件等不会交给 PEPE 处理。不要连续大量发送来证明稳定。

示例整体任务期限为 1800 秒；这是示例配置值，不是延迟保证。单次 HTTP 请求最多约 5 秒，与整个模型任务期限不同。Dot2API task ID 不是模型会话 ID；每条微信输入只传当前文字，电脑 PEPE 主聊记忆是否共享仍未验证。

## 5. 失败与回退

提交是否成功不明、取消或关闭未获远端停止证明时，保留原任务和 unknown，不重投、不换模型、不删库或清队列。停止独立桥只会停止本地新增收发，不等于 PEPE 已停止工作。

回退前保留实际代码、依赖和配置；明确唯一进程身份，再停止本实例、恢复兼容版本并核对原任务。不要更改原 Muse Hook 投递目标或原账号，不以回滚游标、删除收据来消除错误。
